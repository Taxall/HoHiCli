# HoHiCli

HoHiCli добавляет в Home Assistant YAML-платформу `climate` для управления кондиционером по ИК через MQTT. Интеграция выбирает готовый ИК-код из [таблицы команд](custom_components/hohicli/hisense_smart-dc_inverter.json) и публикует его на настроенную тему. Она не считывает состояние кондиционера и не подтверждает, что тот принял команду.

Совместимость проверялась с Home Assistant Core **2026.9.3**. Это результат проверки конкретной версии, а не обещание совместимости со всеми версиями Home Assistant. В документации Home Assistant проверяйте требования к версии Python для выбранного Core.

## Что понадобится

- Home Assistant с настроенной интеграцией [MQTT](https://www.home-assistant.io/integrations/mqtt/) и доступом к MQTT-брокеру.
- ИК-передатчик, который подписан на выбранную MQTT-тему и принимает JSON с полем `ir_code_to_send`. Поддержка именно этого формата и проверка с вашим передатчиком обязательны: совместимость с любым устройством Tuya или любым кондиционером Hisense не гарантируется.
- ИК-таблица в репозитории. Набор кодов ограничивает поддерживаемые режимы и температуры.

Путь команды выглядит так:

```text
Home Assistant climate action
  -> выбор кода из таблицы JSON
  -> MQTT publish (retain=false)
  -> совместимый ИК-передатчик
  -> ИК-сигнал кондиционеру
```

Для большинства команд перед публикацией выдерживается пауза 2 секунды. Команда выключения отправляется без этой дополнительной паузы. ИК-протокол — односторонний: внешняя обратная связь от кондиционера отсутствует.

## Установка

Перед обновлением или ручной установкой сохраните копию конфигурации Home Assistant и текущего каталога интеграции.

### Вручную

1. Скопируйте каталог `custom_components/hohicli` из этого репозитория в `<каталог-конфигурации>/custom_components/hohicli`. Если каталога `custom_components` ещё нет, создайте его.
2. Добавьте платформу `hohicli` в `configuration.yaml`, как показано в разделе [Настройка](#настройка).
3. Проверьте конфигурацию средствами Home Assistant и перезапустите Home Assistant Core, чтобы он загрузил YAML-платформу.

### Через HACS как пользовательский репозиторий

Репозиторий не следует считать опубликованным в каталоге HACS. Для установки как пользовательского репозитория:

1. В HACS откройте меню в правом верхнем углу и выберите **Custom repositories**.
2. Добавьте URL `https://github.com/Taxall/HoHiCli` и выберите тип **Integration**.
3. Установите HoHiCli через HACS, затем перезапустите Home Assistant Core.
4. Добавьте YAML-конфигурацию из следующего раздела, проверьте конфигурацию и снова перезапустите Home Assistant Core.

Названия и расположение пунктов меню HACS могут измениться; сверяйтесь с [актуальной инструкцией HACS](https://www.hacs.dev/docs/faq/custom_repositories/). MQTT настраивается отдельно в Home Assistant: [официальная инструкция MQTT](https://www.home-assistant.io/integrations/mqtt/).

## Настройка

Это YAML-платформа, а не интеграция с мастером настройки: config flow и отдельного экрана первичной настройки нет. В `configuration.yaml` добавьте платформу под ключом `climate`.

Если в файле уже есть верхнеуровневый ключ `climate:`, добавьте элемент платформы в существующий список `climate`, а не создавайте второй такой ключ. Если ключа ещё нет, используйте пример целиком.

### Минимальный пример

```yaml
climate:
  - platform: hohicli
    name: Кондиционер
    unique_id: hisense_living_room
    ir_mqtt_topic: zigbee2mqtt/living_room_ir/set
```

Указанные значения MQTT-топика и формат сообщения должны совпадать с настройками вашего передатчика. В примере приведён лишь пример имени темы, он не настраивает устройство автоматически.

### Полный пример

```yaml
climate:
  - platform: hohicli
    name: Кондиционер в гостиной
    unique_id: hisense_living_room
    ir_mqtt_topic: zigbee2mqtt/living_room_ir/set
    temperature_sensor: sensor.living_room_temperature
    humidity_sensor: sensor.living_room_humidity
```

| Ключ | Требование | Значение и назначение |
| --- | --- | --- |
| `platform` | Обязательный | Всегда `hohicli`. |
| `name` | Задайте явно | Отображаемое имя. Значение по умолчанию кодом не задано. Сохраните прежнее имя при перенастройке, если хотите сохранить связанное с сущностью имя. |
| `unique_id` | Задайте явно | Стабильный уникальный идентификатор сущности. Значение по умолчанию кодом не задано; при переносе или обновлении сохраните прежнее значение. |
| `ir_mqtt_topic` | Обязательный для отправки команд | MQTT-тема, на которую должен подписываться ИК-передатчик. Значение по умолчанию кодом не задано. |
| `temperature_sensor` | Необязательный | Entity ID внешнего датчика температуры; используется только для показа текущей температуры. По умолчанию датчика нет. |
| `humidity_sensor` | Необязательный | Entity ID внешнего датчика влажности; используется только для показа влажности. По умолчанию датчика нет. |

В текущей реализации схема не задаёт значения по умолчанию для YAML-полей и не проверяет их отдельной формой. Укажите `name`, `unique_id` и `ir_mqtt_topic` явно. Настройки датчиков можно не добавлять.

После изменения YAML выполните проверку конфигурации средствами вашей установки Home Assistant и перезапустите Home Assistant Core. Синтаксически правильный YAML сам по себе не проверяет, что MQTT-тема и ИК-передатчик настроены верно.

## Управление и доступные значения

Сущность предоставляет режимы HVAC:

| Параметр | Доступные значения | Начальное значение |
| --- | --- | --- |
| Режим HVAC | `heat`, `cool`, `off` | `off` |
| Целевая температура | От 16 до 30 °C, шаг 1 °C | `23` °C |
| Скорость вентилятора | `auto`, `high`, `medium`, `low` | `auto` |
| Предустановка | `none`, `boost`, `sleep` | `none` |

Средняя скорость `medium` сопоставляется с именем `middle` в ИК-таблице. При `boost` интеграция использует турбо-код и устанавливает 16 °C для охлаждения или 30 °C для нагрева. Предустановка `sleep` в этой реализации переключает диммер (подсветку) кондиционера; это не команда аппаратного режима сна. При выборе `none` диммер, если он включён интеграцией, выключается при отправке следующей команды.

Начальное состояние новой сущности — `off`, 23 °C, `auto`, `none`. При восстановлении Home Assistant интеграция восстанавливает последнее состояние сущности, но не отправляет ИК-команду при запуске. Так как физического подтверждения нет, отображаемое состояние — последнее состояние в Home Assistant и результат отправки команд, а не измеренное состояние кондиционера.

Доступны стандартные действия Home Assistant. Например, включить охлаждение и задать температуру:

```yaml
action: climate.set_temperature
target:
  entity_id: climate.konditsioner_v_gostinoy
data:
  hvac_mode: cool
  temperature: 23
```

Сменить HVAC-режим:

```yaml
action: climate.set_hvac_mode
target:
  entity_id: climate.konditsioner_v_gostinoy
data:
  hvac_mode: heat
```

Установить скорость вентилятора или предустановку:

```yaml
action: climate.set_fan_mode
target:
  entity_id: climate.konditsioner_v_gostinoy
data:
  fan_mode: medium
```

```yaml
action: climate.set_preset_mode
target:
  entity_id: climate.konditsioner_v_gostinoy
data:
  preset_mode: sleep
```

Выключить можно действием `climate.turn_off`, включить — `climate.turn_on`. Последнее включает сохранённый режим нагрева или охлаждения, а если его ещё нет — охлаждение. Замените `climate.konditsioner_v_gostinoy` на entity ID своей сущности. Подробнее: [действия Climate в Home Assistant](https://www.home-assistant.io/integrations/climate/#action-climateset_temperature). Интерфейс Home Assistant позволяет выбрать те же действия в редакторе автоматизаций и на странице инструментов разработчика; подписи и расположение элементов интерфейса могут меняться.

## Температура и внешние датчики

Целевая температура и ИК-таблица используют градусы Цельсия. Сущность сообщает Home Assistant единицу °C; Home Assistant отображает и преобразует её с учётом выбранной единицы интерфейса. Пример `temperature: 23` задаёт 23 °C и рассчитан на конфигурацию Home Assistant с градусами Celsius; при Fahrenheit задавайте нужное значение в единицах, ожидаемых действием Home Assistant. Значение Fahrenheit от внешнего датчика конвертируется в Celsius перед отображением. Температура от датчика не меняет целевую температуру кондиционера и сама по себе не отправляет команду.

Внешние датчики только обновляют атрибуты текущей температуры и влажности. Они должны существовать как сущности Home Assistant и публиковать числовое состояние. Неизвестное или недоступное состояние не используется. Влажность не управляет кондиционером.

## Ограничения и диагностика

- Интеграция работает по принципу optimistic state: после команды она не знает, дошёл ли ИК-сигнал, включился ли кондиционер и какова фактическая температура.
- При потере MQTT-соединения или ошибке публикации Home Assistant может показать ошибку вызова действия. Встроенной очереди повторных отправок и подтверждения ИК-передатчика нет.
- Команды публикуются с `retain=false`, чтобы новый подписчик не получил сохранённый брокером старый ИК-код.
- ИК-коды, допустимые режимы и диапазон температур заданы таблицей в репозитории. Другие температуры и варианты режимов не поддерживаются этой таблицей.
- В таблице есть дополнительные коды, например `quiet`, но в интерфейсе климатической сущности доступны только `auto`, `high`, `medium` и `low`.

Если сущность не появилась, проверьте ошибки загрузки YAML-платформы в журнале Home Assistant, правильность имени `hohicli`, наличие каталога `custom_components/hohicli` и перезапустите Core. Если команда не управляет кондиционером, проверьте MQTT-соединение, точную тему, подписку передатчика и то, что передатчик принимает JSON-поле `ir_code_to_send`. Сначала проверьте доставку сообщения отдельно от ИК-управления; логи Home Assistant не могут подтвердить приём ИК-сигнала кондиционером.

При неверной текущей температуре проверьте числовое состояние датчика и атрибут `unit_of_measurement`. Ошибки преобразования температуры и влажности датчика, а также целевая температура вне поддерживаемого диапазона записываются в журнал Home Assistant. Другие ошибки публикации передаются вызывающей стороне и видны в журнале/результате действия Home Assistant; интеграция не обещает отдельные подробные диагностические сообщения для всех ошибок устройства.

## Обновление

Перед обновлением сохраните конфигурацию и текущую версию интеграции. Через HACS проверьте обновления пользовательского репозитория и обновите интеграцию штатным способом HACS. При ручной установке замените каталог `custom_components/hohicli` целиком файлами новой версии. Затем выполните проверку конфигурации и перезапустите Home Assistant Core. Сохраните `name` и особенно `unique_id`, чтобы Home Assistant продолжил связывать конфигурацию с той же сущностью. После обновления проверьте журнал и выполните осторожную проверку команды.

## Разработка и проверки

Для тестов нужна версия Python, удовлетворяющая метаданным выбранной версии Home Assistant. Home Assistant Core 2026.9.3 требует Python **3.14.2 или новее**; тесты этого проекта выполнялись на Python **3.14.7**. Пример ниже устанавливает версии, использованные для локальных тестов; при выборе другого Core сверяйте его требования к Python и MQTT-зависимостям.

```bash
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install "homeassistant==2026.9.3" "paho-mqtt==2.1.0"
python -m unittest discover -s tests -v
```

Тестовое окружение устанавливает `paho-mqtt==2.1.0` явно. Тесты используют реальные импорты Home Assistant и подменяют транспорт MQTT mock-объектами. Они проверяют логику платформы и формат публикации, но не заменяют проверку на настоящем MQTT-брокере, ИК-передатчике и кондиционере. Отдельной конфигурации pytest или CI в проекте нет.
