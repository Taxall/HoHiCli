# Инструкции для агентов

## Работа с задачами

- Для задач разработки основной агент использует skill `orchestra-orchestrator` из `~/.agents/skills/`.
- Подагент с явно назначенной ролью использует только соответствующий ролевой skill; явная роль важнее роли координатора: `orchestra_routine_worker` → `orchestra-routine-worker`, `orchestra_strong_worker` → `orchestra-strong-worker`, `orchestra_reviewer` → `orchestra-reviewer`, `orchestra_critical_reviewer` → `orchestra-critical-reviewer`.
- Обычные вопросы не требуют оркестрации. Учитывай правила проекта и явные указания пользователя при выборе маршрута. Если требуемый skill или возможность делегирования недоступны, сообщи об этом, не выдумывай запуск агента или результат ревью.
- Перед правками проверь `git status` и изучи релевантный код. Сохраняй уже имеющиеся и параллельные изменения; не перезаписывай чужую работу.
- Не расширяй задачу без необходимости. Не меняй протокол ИК или таблицу кодов без подтверждённых данных о протоколе и ожидаемом поведении.
- Сопоставляй проверку с изменением: для правок только документации достаточно проверить ссылки, примеры и `git diff --check`; не запускай тесты ради документационных правок. Для изменений поведения выбери относящиеся к ним проверки и тесты, не утверждай, что проверено оборудование, если этого не было.
- Не выполняй commit, push или публикацию без явного поручения пользователя.

## Карта проекта

- `custom_components/hohicli/climate.py` — YAML climate-платформа, режимы, состояние сущности и датчики.
- `custom_components/hohicli/sender.py` — загрузка JSON-таблицы и публикация команд через MQTT.
- `custom_components/hohicli/const.py` — домен, ключи конфигурации, атрибуты и пределы температуры.
- `custom_components/hohicli/hisense_smart-dc_inverter.json` — готовые ИК-коды. Это данные протокола, не редактируй их для косметического рефакторинга.
- `custom_components/hohicli/manifest.json` — метаданные интеграции и версия.
- `tests/test_climate.py` — unittest-проверки логики с реальными импортами Home Assistant и mock MQTT-транспортом.
- `README.md` — установка, настройка, использование и ограничения для пользователей.

## Инварианты реализации

- Это YAML-платформа без config flow и UI-мастера. Ключи YAML и дополнительные атрибуты состояния — публичный интерфейс: сохраняй их имена и смысл при рефакторинге. Атрибуты состояния: `power_status`, `dimmer_status`, `target_temperature`, `last_on_operation`. Основные ключи `name`, `unique_id`, `ir_mqtt_topic` нужно задавать в YAML; `temperature_sensor` и `humidity_sensor` необязательны.
- ИК-таблица и сущность используют Celsius; температуры таблицы — целые 16–30 °C. Сохраняй корректное преобразование единиц Home Assistant и датчиков.
- В Home Assistant средняя скорость называется `medium`, а в таблице ИК-кодов — `middle`; отображение между ними должно сохраняться.
- Доступные режимы сущности: `heat`, `cool`, `off`; скорости: `auto`, `high`, `medium`, `low`. Предустановки `none`, `boost`, `sleep`; `sleep` переключает диммер, не аппаратный режим сна.
- Новое состояние: `off`, 23 °C, `auto`, `none`. Восстановление состояния после старта не должно автоматически передавать ИК-команду.
- Команды защищены asyncio-lock: удерживай последовательность обновления состояния и отправки так, чтобы параллельные действия не переставляли ИК-команды. Метод `_async_send_command_locked` вызывается только с уже захваченным lock и не должен повторно захватывать его.
- MQTT публикует JSON вида `{"ir_code_to_send": "..."}` на настроенную тему с `retain=False`. Для большинства safe-команд задана пауза 2 секунды; выключение публикуется напрямую.
- Ошибки MQTT не скрывай и не отмечай отправленную команду как успешную до завершения публикации. Внешние датчики только обновляют отображаемые значения, не запускают управление.
- Слушатели изменений датчиков должны удаляться вместе с сущностью; файловые операции инициализации не должны блокировать event loop Home Assistant.

## Проверки и версии

- Перед запуском тестов уточни поддерживаемую версию Python из metadata установленного Home Assistant (`python -c 'from importlib.metadata import metadata; print(metadata("homeassistant").get("Requires-Python"))'`) и используй Python в этом диапазоне. Не угадывай требования по версии интеграции.
- Metadata Home Assistant Core 2026.9.3 требует Python >=3.14.2; тесты проекта проверялись на Python 3.14.7 с `paho-mqtt==2.1.0`. Устанавливай совместимую версию `paho-mqtt` явно в тестовом окружении: не рассчитывай, что установка пакета Home Assistant автоматически поставит зависимости каждого integration component.
- Основная команда тестов: `python -m unittest discover -s tests -v` из корня репозитория при установленных зависимостях Home Assistant.
- Перед сдачей изменений проверь `git diff --check` и просматривай итоговый diff. Запускай проверки, подходящие масштабу изменения; отсутствие нужной зависимости или проверки укажи явно.
